## 4. ЧТО СОБИРАТЬ И НА КАКОМ УРОВНЕ ХРАНИТЬ

Каждый факт хранится там, где он реально определяется. Один проверенный факт покрывает
все строки под ним. У поколения один клиренс, а не пятнадцать.

| № | Поле | Уровень хранения | Основной источник |
|---|---|---|---|
| 1 | Идентификация (марка, линейка, поколение, годы, кузов, места) | поколение | EPA, vPIC |
| 2 | Двигатель (заводской код, объём, цилиндры, наддув, впрыск) | семейство двигателя + конфигурация | EPA, руководство |
| 3 | Коробка (тип, число передач, обозначение) | конфигурация | EPA, руководство |
| 4 | Привод | конфигурация | EPA |
| 5 | Мощность и момент | конфигурация (меняется по годам) | руководство, EPA |
| 6 | Топливо (тип, октановое число), расход, бак | конфигурация | EPA, руководство |
| 7 | Масло двигателя | семейство двигателя | руководство |
| 8 | Прочие жидкости и ёмкости | поколение / коробка | руководство |
| 9 | ТО | поколение (Приложение C) | руководство / maintenance-документы |
| 10 | Шины | конфигурация / пакет колёс | руководство, табличка давления |
| 11 | Размеры (длина, база, клиренс, багажник, масса) | поколение | руководство, пресс-материалы |
| 12 | Узлы (подвеска перед/зад, тормоза, рулевое) | поколение | руководство, пресс-материалы |
| 13 | Recalls | поколение + годы + применимость | NHTSA Recalls API |
| 14 | Известные проблемы | двигатель / коробка / поколение + годы | NHTSA complaints, TSB, recalls |
| 15 | Источники | у каждого факта | — |

**Поле масла — общее для всех марок:**
- вязкость (например `0W-20`);
- стандарт (`API SP`, `ILSAC GF-6`, `ACEA C3` — что указано);
- заводской допуск, если он есть у марки (`MB 229.5`, `BMW LL-01`, `VW 504 00`, `dexos1`
  и т.д.), иначе NULL;
- объём с фильтром.

Для электромобилей поле масла двигателя не заполняется; заполняются ОЖ, тормозная
жидкость, масло редуктора — если указаны в руководстве.

**ТО — строго структурно (по этим данным раздел «Гараж» будет напоминать владельцу):**
Каждая работа регламента — отдельная запись, не текст:
- работа (замена масла, масляного фильтра, воздушного, салонного, ОЖ, тормозной жидкости,
  жидкости АКПП/редукторов, свечей, ремня ГРМ, приводного ремня и т.д.);
- интервал в км и в месяцах, правило «что наступит раньше»;
- условия: нормальные / тяжёлые — отдельно, если указаны;
- первая замена и последующие, если отличаются (например ОЖ: первая на 160 000 км,
  дальше каждые 80 000 км);
- система ТО марки: фиксированный интервал или бортовая система (Oil-Life Monitor, CBS,
  Maintenance Minder, Service A/B). Для бортовых систем записать предельный интервал из
  руководства («не позже чем…»), если он указан;
- **привод ГРМ: ремень или цепь** — на уровне семейства двигателя, и интервал замены
  ремня, если он есть. Для владельца это одно из самых важных напоминаний;
- источник и страница у каждой записи.

Если регламент лежит в отдельном документе (Toyota, Lexus — отдельная книжка ТО),
искать этот документ так же, как руководство.

Единицы: в базе метрические (л, км, мм, кг), если схема не требует иного. Исходное значение
и единица — в evidence. Пересчёт только по фиксированным коэффициентам из одного модуля.

## 5. ИСТОЧНИКИ И ПРИОРИТЕТ

1. **EPA fueleconomy.gov** — bulk `vehicles.csv`, один раз в `_shared/raw/`, разбор локально.
   Каркас конфигураций: год, модель, объём, цилиндры, коробка, привод, топливо, расход.
2. **NHTSA vPIC** (https://vpic.nhtsa.dot.gov/api/):
   - список моделей по годам: `GetModelsForMakeYear`;
   - для массовой работы скачать **standalone-базу vPIC** (https://vpic.nhtsa.dot.gov/downloads/)
     в `_shared/raw/` и работать с ней локально — у API есть автоматическое ограничение
     частоты запросов;
   - расшифровка VIN-образцов: `DecodeVinValues` или пачкой до 50 штук `DecodeVINValuesBatch`;
   - **размеры**: `GetCanadianVehicleSpecifications?year=&make=&model=&units=Metric` —
     длина, ширина, высота, база, колея перед/зад, свесы, снаряжённая масса, развесовка
     (данные Минтранса Канады). Достоверность SECONDARY: канадская версия, использовать для
     поля размеров, если совпадает с другим источником или другого нет; расхождение с
     руководством — в журнал конфликтов, руководство главнее.
3. **NHTSA Recalls API** — `api.nhtsa.gov/recalls/recallsByVehicle` по линейке и году.
4. **NHTSA Complaints API** — жалобы по линейке и году, для паттернов.
5. **NHTSA Manufacturer Communications (TSB)** — flat file со страницы
   nhtsa.gov/nhtsa-datasets-and-apis (раздел Manufacturer Communications, словарь полей
   `MfrComms.txt`). Сводки бюллетеней по году/марке/модели с узлом. В файле есть не все
   бюллетени — это учитывать в оценке.
6. **Официальные руководства владельца** — порталы из Приложения B. Главный источник для
   полей 7–12. Скачанный PDF в `raw/`, в evidence — URL и номер страницы.
   Извлечение текста из PDF:
   - сначала `pdftotext -layout`; если текст пустой или мусорный (так бывает у Kia/Hyundai
     со своими шрифтами) — `pypdfium2`; если и он не справился — рендер страницы в картинку
     и OCR (tesseract);
   - нужный раздел искать по оглавлению: обычно глава Specifications / Capacities /
     Maintenance data в конце руководства;
   - числа с потерянными символами (`100010g` вместо `100±10 g`, слипшиеся диапазоны,
     перепутанный порядок единиц в таблице lbs/kg) **сверять по картинке страницы**;
     не удалось однозначно прочитать — NULL и запись в журнал.
7. **Vehicle Databases (только если VDB = да).** Ключ владелец задаёт в переменной окружения
   `VDB_API_KEY`. Эндпоинт: `GET https://api.vehicledatabases.com/ymm-specs/v3/{year}/{make}/{model}/{trim}`,
   заголовок `x-authkey`. Кредиты ограничены:
   - перед серией запросов показать владельцу список и число запросов и ждать «да»;
   - каждый ответ сохранять в `raw/vdb/` и не запрашивать повторно;
   - брать: размеры, массу, шины и давление, тормоза (диаметры), рулевое, бак, расход, мощность/момент;
   - брать: оценки стоимости ремонтов (блок repair: запчасти + работа, мин/макс, USD) — как
     относительный показатель дороговизны узла (например замена коробки);
   - **не брать**: коды двигателя и коробки (это внутренние коды опций, не заводские),
     блок maintenance (шаблонный), стоимость владения;
   - тип подвески — только со сверкой по второму источнику;
   - статус источника — вторичный, не OFFICIAL_SOURCE.
8. **Вторичные** (Edmunds, KBB, Car and Driver, MotorTrend) — только для полей, которых нет
   выше. Для чисел, влияющих на вывод пользователю (объём масла, клиренс), нужны **два
   независимых источника**.

9. **Дополнительные источники — используются, но с пониженной достоверностью.**
   Ни один источник не идеален. Задача — взять из каждого полезное, пометить уровень
   достоверности и **автоматически сверить** с остальными. Владелец вручную ничего не сверяет.

   | Источник | Что брать | Достоверность | Правило |

   | CarComplaints.com | «худшие проблемы» по модели и году, средняя стоимость ремонта и пробег, тренд жалоб по годам | SECONDARY (жалобы владельцев) | сырой ответ сохранять в `raw/`; совпадение с паттерном NHTSA повышает вероятность проблемы; без NHTSA — запись с пометкой «по отзывам владельцев» |

## 6. ПРАВИЛА ДОСТОВЕРНОСТИ

Каждый факт имеет evidence: источник (название + URL или путь в `raw/`), дата получения,
применимость (поколение, годы, двигатель, коробка, рынок US), confidence и verification
status из словаря схемы.

Конфликт источников (расхождение больше округления): оба значения в evidence, в основное
поле — первоисточник (руководство / EPA / NHTSA), запись в журнал конфликтов.

Валидатор перед записью:
- модельный год в пределах ГОДОВ и годов поколения;
- объём двигателя соответствует коду двигателя;
- мощность в разумном диапазоне для класса;
- объём масла легкового ДВС 3–12 л; у электромобиля масла двигателя нет;
- у конфигурации есть двигатель (или электромотор), коробка, привод;
- нет факта без evidence.

Не прошло — не записывается, уходит в журнал.

**Как уровень достоверности влияет на показ пользователю** (записать в данные, чтобы
отчёт приложения мог это учитывать):
- OFFICIAL_SOURCE или два независимых источника совпали — показывается как факт;
- один вторичный источник — показывается с пометкой (например «по данным справочников»);
- только отзывы владельцев — показывается в экспертном выводе как «владельцы сообщают…»;
- источники противоречат друг другу и решить нельзя — поле не показывается, конфликт в журнале.

## 7. ИЗВЕСТНЫЕ ПРОБЛЕМЫ — МЕТОДИКА

Проблема попадает в базу, если выполнено хотя бы одно:
- recall NHTSA по узлу;
- TSB / manufacturer communication по узлу;
- паттерн в NHTSA complaints: один узел и симптом по одному поколению и двигателю
  (стартовый порог — 10 жалоб, вынести в константу).

Дополнительно:
- паттерн в CarComplaints совпал с паттерном NHTSA по тому же узлу и годам — вероятность
  повышается на ступень, стоимость ремонта и пробег берутся из CarComplaints с пометкой;
- паттерн есть только в CarComplaints (заметный, повторяющийся) — записать с достоверностью
  SECONDARY и пометкой «по отзывам владельцев», severity не выше MEDIUM.

Вторичная инженерная публикация уточняет описание, симптомы и способ проверки.

Для каждой проблемы: узел, название, симптомы, причина (если названа в источнике),
последствия, как проверить при осмотре, типовое решение, применимость (поколение,
двигатель/коробка, годы), severity (LOW / MEDIUM / HIGH; HIGH — безопасность или дорогой
ремонт силового агрегата), probability по правилу из констант (COMMON — паттерн жалоб выше
порога и TSB; OCCASIONAL — паттерн или TSB; RARE — только recall с ограниченной партией),
ссылки на основания.

Проблему двигателя привязывать к двигателю, коробки — к коробке. Не дублировать на каждую
конфигурацию.

Правила:
- Только домен производителя даёт статус OFFICIAL_SOURCE.
- Динамический портал не читается — искать прямой PDF поиском по домену
  (`site:<домен> <модель> <год> owner's manual pdf`).
- **Нужен VIN (BMW, Audi, VW):** составить список «линейка + год» и попросить у владельца
  по одному VIN-образцу на комбинацию. До получения — поля из руководства пустые,
  причина в журнале.
- **Mitsubishi (аккаунт):** пробел; владелец может положить PDF в `raw/owner_supplied/`.
- **Годы вне покрытия портала** (Land Rover MY14):
  искать прямой PDF на домене производителя; не нашёлся — пусто с причиной.
- Жидкости АКПП/дифференциала в руководствах часто нет («обратитесь в сервис») — тогда
  пусто с причиной, не искать замену во вторичных источниках.

**Запасной вариант — копии руководств владельца (carmans.net и подобные).**
Использовать, когда официальный портал требует VIN или аккаунт (BMW, VW, Audi, Mitsubishi)
или не покрывает год (Land Rover MY14):
1. Сначала искать на официальном домене; копию — только если там нет.
2. Проверить, что это **американское издание и нужный модельный год**: обложка, номер
   документа, упоминание USA, единицы (мили/кварты). Не подтверждается — не использовать для
   US-записей, а сохранить в библиотеку других рынков (Приложение D).
3. PDF сохранить в `raw/`, в evidence: «заводское руководство владельца, копия с <сайт>»,
   URL, номер страницы. Статус — SECONDARY (документ заводской, но получен не от производителя).
4. Если позже найден официальный PDF — данные сверить и перевести в OFFICIAL_SOURCE.
5. На главной carmans.net видны: Ford, Toyota, Chevrolet, VW, GMC, Cadillac, Lincoln, Chrysler,
   RAM, Dodge, Kia, Mazda, Nissan, BMW, Honda, Mini, Tesla, Volvo, Jeep. Остальные марки —
   проверить поиском по сайту.

6. **mycarusermanual.com** — обходится **полностью** по всем маркам и линейкам из
   Приложения A (процедура — Приложение E). Есть Hyundai, Kia, Audi, BMW, Honda, Volvo,
   Mini и др. Руководства лежат HTML-текстом по разделам, без PDF. Особенности:
   - разбивка **по поколениям** (например Tucson 2004–2009), а не по годам — значения
     привязывать ко всему диапазону только если они не менялись; если в других источниках
     есть расхождения по годам — в журнал конфликтов;
   - **часто международные издания**: признаки не-US — дизели, не продававшиеся в США,
     пометки «E.C», правый руль, Ближний Восток, классы ACEA без API/ILSAC, только литры.
     Такое издание не идёт в US-записи, а сохраняется в библиотеку других рынков
     (Приложение D) с определённым рынком;
   - объёмы обычно в отдельном разделе спецификаций — открывать его, а не только раздел ТО.
     У поколения обычно три раздела спецификаций, адреса вида
     `https://www.mycarusermanual.com/<марка>/<модель>/<кузов>/<годы>/vehicle-specifications--engine`,
     `.../vehicle-specifications--measurement` (размеры),
     `.../vehicle-specifications--lubrication-chart` (масла, жидкости, объёмы).
     Точные адреса брать по ссылкам со страницы поколения, не угадывать;
   - таблицы спецификаций **разбирать по структуре HTML** (строки, столбцы, заголовки
     столбцов-двигателей). Как плоский текст они разваливаются: подписи отделяются от
     значений, и значения одного двигателя легко приписать другому. Каждое значение
     привязывать к конкретному двигателю по столбцу; неоднозначно — NULL и журнал.

**Автоматическая загрузка с carmans.net (делает Claude Code, не владелец):**
1. Адрес страницы руководства обычно `https://www.carmans.net/<год>-<марка>-<модель>/`
   (пример: `/2018-toyota-camry/`, `/2018-ford-fusion/`). Бывают варианты
   (`/2021-kia-optima-incl-hybrid/`, суффиксы `-2`) — точный адрес брать со страницы
   категории марки/модели (`/category/<марка>/…`), а не угадывать.
2. Страница — встроенный просмотрщик PDF. Сначала скачать HTML одной страницы и найти,
   откуда просмотрщик берёт файл (`iframe src`, параметр `file=`, прямая ссылка на `.pdf`).
   Логику поиска ссылки написать под реальную разметку, а не по предположению.
3. Скрипт `scripts/fetch_owner_manuals.py`: на вход список «марка, модель, год», на выходе
   PDF в `data_work/<марка>/raw/manuals/<год>-<модель>.pdf` + `manifest.csv`
   (марка, модель, год, URL страницы, URL PDF, размер, sha256, дата, статус).
4. Уже скачанные файлы (есть в manifest с тем же sha256) не качать повторно.
5. Пауза 2–5 секунд между запросами, не больше одного запроса одновременно.
6. После загрузки — автоматическая проверка издания по тексту PDF (pdftotext):
   маркеры американского издания (`enUSA`, `United States`, суффикс `_U` в колонтитуле у Toyota,
   мили/кварты). Не подтвердилось — определить рынок издания, статус `other_market`, файл
   сохранить в библиотеку (Приложение D).
7. Нет страницы или PDF — статус `not_found`, перейти к следующему, не останавливаться.
8. Итог загрузки — в отчёт: сколько скачано, сколько не найдено, сколько ушло в библиотеку
   других рынков (по рынкам).

## ПРИЛОЖЕНИЕ E — ПОЛНЫЙ ОБХОД mycarusermanual.com

Обязательный этап для каждой МАРКИ. Не точечные страницы, а **всё руководство целиком**
по каждой линейке из Приложения A и каждому поколению на сайте.

### 1. Объём обхода
- Марки и линейки — из Приложения A (или параметр ЛИНЕЙКИ).
- Поколения — **все**, что есть на сайте для этой линейки и пересекаются с ГОДАМИ.
  Поколения целиком вне ГОДОВ — пропустить, отметить в отчёте.
- Разделы — **все разделы руководства** поколения: ТО, спецификации (двигатель, размеры,
  смазка), шины, предупреждения, лампы, предохранители и всё остальное, что есть на сайте.
- Издания всех рынков (US, CA, EU, GCC, KR, CN, GENERAL). Американские идут в US-записи,
  остальные — в библиотеку (Приложение D).

### 2. Навигация — только по ссылкам с сайта, адреса не угадывать
1. Главная → страница марки (`/<марка>`) → страница модели (`/<марка>/<модель>`).
2. Страница модели → список поколений (`/<марка>/<модель>/<кузов>/<годы>`).
3. Страница поколения → полный список разделов (оглавление и блоки «Related Topics»).
4. Обойти каждый раздел и каждый его подраздел (в т.ч. `vehicle-specifications--engine`,
   `--measurement`, `--lubrication-chart` и любые другие найденные).
5. Сопоставить названия моделей сайта с нашими линейками с учётом переименований
   (Приложение C: Optima/K5, ML/GLE, GL/GLS, GLK/GLC, FX/QX70 и т.д.). Не нашлась
   линейка на сайте — `not_on_site` в отчёт.

### 3. Что сохранять
- Сырой HTML каждой страницы:
  `data_work/_mcum/raw/<марка>/<модель>/<кузов>_<годы>/<раздел>.html`
- Извлечённый текст рядом: `<раздел>.txt`
- Реестр `data_work/_mcum/manifest.csv`: марка, модель, кузов, годы поколения, раздел,
  URL, HTTP-статус, sha256, дата, определённый рынок издания.
- Структурированные данные по поколению:
  `data_work/_mcum/parsed/<марка>/<модель>/<кузов>_<годы>.json` — у каждого значения
  URL страницы-источника.

### 4. Что извлекать в структуру
- двигатели: тип, объём, диаметр × ход, порядок работы, холостой ход, зажигание, зазоры;
- размеры и массы;
- смазка: масло (вязкость, класс, допуск, объём), ОЖ, жидкости АКПП/МКПП/DCT/CVT,
  тормозная, редукторы, раздатка, гидроусилитель — с объёмами;
- шины и диски, давление, момент затяжки;
- топливо (октановое число, бак);
- регламент ТО (нормальные и тяжёлые условия), если есть раздел;
- любые другие таблицы спецификаций, найденные в руководстве.

Таблицы — **по структуре HTML** (строки, столбцы, заголовки столбцов-двигателей),
не плоским текстом. Значение привязывается к конкретному двигателю по столбцу.
Неоднозначно — NULL и журнал.

### 5. Рынок издания
- Определяется **на уровне поколения целиком** по признакам из Приложения D
  (дизели вне US, «E.C», правый руль, Middle East, ACEA, «U.S. only», мили/кварты).
- US → данные идут в US-записи со статусом SECONDARY и пометкой
  «руководство владельца, копия с mycarusermanual.com».
- Остальные → библиотека `_library/<РЫНОК>/` + `staging_specs.csv`.

### 6. Поколение против модельного года
- Значения сайта относятся ко всему диапазону поколения. Привязывать их к годам внутри
  диапазона, только если более точные источники (руководство конкретного года, EPA)
  не противоречат.
- Расхождение с источником конкретного года — источник конкретного года главнее,
  расхождение в журнал конфликтов.

### 7. Правила обхода
- Один запрос одновременно, пауза 2–5 с.
- Повтор до 3 раз с нарастающей паузой при таймауте или 5xx.
- При 403/429 — увеличить паузу; при повторе остановить обход марки и сообщить в отчёте.
- Докачка: страницы, уже есть в manifest со статусом 200, повторно не скачивать.
  Обход можно прервать и продолжить с того же места.

### 8. Отчёт по обходу (часть итогового отчёта)
- по каждой линейке: какие поколения найдены, сколько разделов скачано, какой рынок
  издания у каждого поколения;
- линейки, которых нет на сайте;
- сколько значений извлечено в структуру по типам (двигатели, размеры, смазка, шины, ТО);
- ошибки и пропуски.
