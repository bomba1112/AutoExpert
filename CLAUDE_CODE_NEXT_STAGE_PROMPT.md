## ЭТАП A — ИМПОРТ ОБРАЗЦОВ TEOALIDA (со сверкой точности)

### A.1 Подготовка
- Файлы в `C:\AutoExpertData\raw\teoalida\`. Дубли (`__1_`, `__2_`, `(1)`) определить по sha256
  и обрабатывать один раз. Каждый файл — в manifest и `raw_documents`.
- Реестр источника `teoalida`: уровень SECONDARY, права «только исследование».
- Заголовки таблиц начинаются не с первой строки (служебные строки, счётчики, подписи «SAMPLE»):
  строку заголовков находить по содержимому.
- Это **образцы** (часть марок и моделей). Импортёры писать так, чтобы полная база того же
  формата загружалась тем же скриптом.
- Все значения Teoalida — SECONDARY: сами по себе только `SECONDARY_NOTE`; совпадение с
  официальным источником — второе подтверждение, официальный остаётся главным.

### A.2 Ravenol-SAMPLE.xlsx — объёмы жидкостей, коды агрегатов, интервалы
Колонки: `makeLabel, modelLabel, typeLabel, partName, partCode, capacities, useType, intervals,
productCode, productLabel`.
- Рынок из `makeLabel`: `(USA)`, `(USA / CAN)` → US; `(EU)` → EU; `(CHN)` и китайские СП → CN;
  `(RUS)`, `(BRA)`, `(TUR)` → библиотека.
- `typeLabel` (пример `320i xDrive, N20 (2012-2015)`): версия, код двигателя, **годы производства**
  (не модельные годы — сопоставлять по пересечению; неоднозначно — не расширять применимость,
  запись в журнал).
- Брать:
  - `Engine`: `partCode` = заводской код двигателя; `capacities` = объём масла;
  - `Transmission, automatic/manual`: `partCode` = **код коробки** (например ZF GA8HP),
    `capacities` = объём жидкости коробки;
  - `Cooling system`, `Differential…`, `Transferbox`, `Power steering…`,
    `Hydraulic brake/clutch…`: объёмы и тип системы;
  - `intervals` + `useType` → `maintenance_schedule_items`:
    `Change 10000 miles/ 12 months` → мили/км (через модуль единиц) + месяцы, «что раньше»;
    `Check … | Change …` → две работы; `Normal` / `Severe` → условия;
    `Flexible (max)` → **предельный интервал** для бортовой системы (CBS, Oil-Life);
    `Flexible (on board maintenance system)` → тип системы без числа;
    `First change only` → только первая замена.
  - Уточнения в `partName` («as of 03/2020», «up to production date …») — условие применимости.
  - `Capacity 8,5 litre` — десятичная запятая.
- **Не брать:** `productLabel` / `productCode` (это масла бренда Ravenol). Вязкость и допуски
  по названиям продуктов **не выводить**.

### A.3 Year-Make-Model-Trim-Specs (США, по комплектациям)
Только US-комплектации наших линеек, MY2014–2026. Брать: габариты, колея, **клиренс**, углы,
**радиус разворота**, Cd, объём салона, **багажник**, массы, грузоподъёмность, буксировка,
цилиндры, объём, мощность/момент с оборотами, клапаны и ГРМ, привод, коробка, 0–60, топливо,
бак, расход EPA, данные EV, размеры салона, **подвеска**, **шины и диски**, безопасность,
рейтинг NHTSA, **platform code / generation**. Единицы — в метрические через модуль единиц.
Не брать в базу: цены, цвета, обзоры, плюсы/минусы, экспертные оценки (остаются в raw).

### A.4 TireSize-SAMPLE.xlsx
Размеры шин по году/марке/модели/комплектации → поле 10, только US наших линеек.

### A.5 Year-Make-Model, Car-Models-List, Car-Nameplates-List
- Коды поколений/платформ (например закрыть пробел XV50/XV70 у Camry) — вторичный факт

### A.7 Другие рынки → библиотека

### A.8 Сверка точности — до записи каждого файла

Данные в БД на этом этапе **не менять** — только код и интерфейс.

1. **Флаг `show_us_tech_facts`:** включён в preview/dev, **выключен в production** по умолчанию.
   Существующую логику прав (`commercial_fact_overlay.py`, `CLAIM_FIELDS`, `COMMERCIAL_OK`)
   не ломать; production без флага ведёт себя как сейчас.
2. **Backend:** сервис сборки фактов для видимой конфигурации: подходят только факты с
   совпадающей областью применения (линейка, поколение, годы, ключ двигателя/коробки,
   силовая установка, издание/кузов, комплектация). **Самый конкретный уровень побеждает:**
   конфигурация → семейство двигателя → поколение. `FACT` — показывать; `SECONDARY_NOTE` —
   с пометкой «по данным справочников»; `OWNER_REPORTS` — только в слабых местах,
   «владельцы сообщают»; `HIDDEN_CONFLICT` — **никогда не показывать**. Метрические единицы.
   Источник у каждого значения (для свёрнутого уровня «Источники»). Кэш на конфигурацию.
3. **Интерфейс (Flutter + web), по утверждённому макету:**
   - **Техническая часть** по категориям: Двигатель · Коробка · Топливо · Масла и жидкости ·
     Кузов и размеры · Подвеска и тормоза · Салон и практичность;
   - **Слабые места:** название, узел, серьёзность, вероятность, симптомы, как проверить;
   - **Сервисные кампании:** номер, узел, суть, годы;
   - **ТО:** работа, интервал (км и месяцы, «что раньше»), условия, первая/последующие;
     ориентировочные записи — с пометкой «ориентировочно»; нет записей — вкладка скрыта.
   - Пустое поле и пустая категория **скрываются**: никаких «нет данных» и прочерков.
   - Подписи на RU и AZ. Экран нормально выглядит и при 5 строках, и при 40.
4. **Тесты:** выбор уровня, фильтр по силовой установке и годам, скрытие HIDDEN_CONFLICT и
   пустого, флаг выключен — production без изменений; виджет-тесты; смоук web.
5. **Скриншоты** web preview с флагом в `data_work/ui/screens/`: Toyota Camry 2020 (2.5),
