1. СМЫСЛ ПРОДУКТА — НЕ МЕНЯТЬ

Auto Expert помогает покупателю:

— понять автомобиль и его модификацию до покупки;
— сравнить два или три варианта;
— разобраться в конкретном предложении по ссылке или VIN;
— получить обоснованный экспертный вывод и обсудить его в чате.

VIN — необязательный способ ввода и дополнительный источник истории.

БЕЗ VIN должны работать:
— разбор автомобиля;
— сравнение автомобилей;
— анализ конкретного объявления.

Пользователь не создаёт карточки автомобилей и не наполняет нашу базу.

Он сообщает, какой автомобиль его интересует. Приложение самостоятельно получает доступные сведения, сопоставляет их и готовит ответ.

Основной результат:
содержательное досье в приложении + контекстный чат + профессиональный PDF.

Это не техническая консоль, не список источников, не голая таблица характеристик и не анкета вместо экспертизы.

3. СЦЕНАРИЙ «УЗНАТЬ ОБ АВТОМОБИЛЕ»

Предусмотри свободный ввод и удобный выбор по параметрам.

Пример запроса:
«Toyota Corolla 2020 1.8 гибрид, рынок США».

Это пример пользовательского ввода, а не зашитая машина и не гарантия существования любой введённой комбинации.

Основные поля:
— марка;
— модель;
— год;
— исходный рынок.

Если рынок неизвестен:
«Не знаю», а не блокировка.

Дополнительные параметры:
— двигатель / объём;
— бензин / дизель / гибрид / электро;
— коробка;
— привод;
— комплектация.

Используй постепенное уточнение.
Сначала простое, затем только существенные различия.

Не показывай двадцать обязательных полей.
Не требуй заводские коды двигателя и коробки.

Подсказки и варианты должны основываться на доступных данных.
Если сочетание параметров не подтверждается, покажи понятные найденные варианты. Не подменяй автомобиль молча.

Различай:
— исходный рынок;
— страну производства;
— страну эксплуатации покупателя.

Перед анализом покажи компактную карточку выбранной версии с действием «Изменить».

Если версия определена достаточно точно, не вставляй дополнительные обязательные подтверждения.

Далее:

«Получить разбор»
→ реальная подготовка
→ досье
→ вопросы эксперту / сравнение / PDF.

— заявленный пробег;

— ссылку на источник и дату получения;
— доступные фотографии;

После импорта покажи компактную карточку:

Автомобиль
Фото при наличии
Цена
Пробег
Источник

Действия:
«Разобрать предложение»
«Уточнить данные»

ОТСУТСТВИЕ VIN НЕ БЛОКИРУЕТ АНАЛИЗ.

Конкретное объявление без VIN — полноценное предложение о конкретном автомобиле.

Привяжи его к собственному идентификатору объявления / снимка страницы и к модели / версии.

Не создавай фиктивный VIN.

Используй:
— характеристики версии;
— заявленные данные предложения;
— контекст покупателя.

Не объявляй пробег, безаварийность или состояние подтверждёнными только потому, что это написал продавец.

Понятно различай:

«Характеристики выбранной версии»
«Указано продавцом»
«Найдено в истории автомобиля»

Последний блок — только при наличии соответствующего источника.

VIN можно добавить позднее:
«Дополнить VIN-историей».

Уже выполненный разбор сохраняется.


4.2. ИМПОРТ С РАЗНЫХ САЙТОВ

Используй общий интерфейс импорта объявлений, структурированные метаданные страниц, где они доступны, и адаптеры источников.

Turbo.az — первый источник для проверки, а не единственный сайт, под который пишется весь продукт.

Поддержку сайта доказывай реальным импортом.
Не обещай поддержку всех сайтов мира.

Если страница удалена, недоступна или блокирует разрешённое получение данных:

— объясни причину;
— сохрани введённую ссылку;
— предложи вставить описание объявления либо продолжить по параметрам.

Это запасной путь, а не обязательное ручное наполнение базы.

Не обходи CAPTCHA, авторизацию, платный доступ и ограничения источника.

Защити серверную загрузку URL:
— запрети обращения к localhost, приватным сетям и служебным адресам;
— проверяй перенаправления;
— ограничь время, размер и тип загружаемых данных.


4.3. ВВОД VIN

VIN автоматически определяет автомобиль и ведёт в тот же разбор.

Доступная история добавляется к техническому досье, а не заменяет его.

Отсутствие данных одного VIN-провайдера не должно останавливать разбор модели.


5. СЦЕНАРИЙ «СРАВНИТЬ АВТОМОБИЛИ»

Реализуй настоящее сравнение двух или трёх автомобилей.

Добавлять вариант можно:
— через параметры;
— по ссылке;
— по VIN.

Разрешены смешанные варианты:
например, одна модель без объявления и два конкретных предложения.

На карточках и в отчётах есть:
«Добавить к сравнению».

Корзина сравнения сохраняется при навигации.
Вариант можно заменить или удалить.

С двумя машинами сравнение уже работает.
Третья необязательна.

Не требуй длинную обязательную анкету.

По желанию пользователь указывает приоритеты:
— экономичность;
— надёжность;
— комфорт;
— стоимость содержания;
— пространство;
— динамика;
— перепродажа.

Дополнительный контекст:
страна / город эксплуатации, дороги, приблизительный месячный пробег.

Сравнивай по одинаковым критериям:
двигатель / силовая установка, коробка, расход, обслуживание, сильные и слабые стороны, практичность, отзывы.

Местные цены и ликвидность включай только при наличии подходящих актуальных данных.

На телефоне:
— закреплённые названия вариантов;
— компактные строки;
— раскрытие подробностей;
— понятные отличия.

Не помещай три длинных досье в узкие колонки.

Разделяй сравнение моделей и риски конкретных предложений.
Повреждения одного экземпляра не делают всю модель плохой.

Финал сравнения:

Какой вариант лучше отвечает выбранным приоритетам?
Почему?
Чем уступает другим?
При каких условиях рекомендация меняется?

Без выдуманных баллов.
Без вывода «меньше найденных жалоб = выше надёжность».

Предусмотри чат по всему сравнению и PDF сравнения.
Факты разных автомобилей не смешиваются.


6. СТРУКТУРА И СОДЕРЖАНИЕ ДОСЬЕ

Сначала автомобиль.
В конце — экспертный вывод.

Основной порядок:

1. Автомобиль: паспорт выбранной версии, фото при наличии.
2. Двигатель / силовая установка.
3. Коробка и привод.
4. Подвеска, рулевое, тормоза.
5. Кузов и электроника.
6. Расход и обслуживание.
7. Сильные и слабые стороны.
8. Отзывы владельцев.
9. Существенные отзывные кампании и технические бюллетени.
10. Конкретное предложение / история / фотографии — когда применимо.
11. Экспертный вывод — последний содержательный раздел.

Источники доступны из соответствующих утверждений и отдельным справочным блоком.

Технические подробности источников не замещают анализ.

Паспорт:
модель, год, рынок, кузов, места, двигатель, коробка, привод, размеры, колёсная база, багажник и другие подтверждённые характеристики.

Цвет и индивидуальные опции конкретного экземпляра не выводить из общего каталога версии.

Основной текст технического раздела:
короткий и содержательный, ориентир 60–100 слов плюс компактные характеристики.

Подробности открываются по желанию.
Не сокращай полезную глубину до пары пустых фраз.

Двигатель:
устройство, мощность, топливо, масло, обслуживание, существенные достоинства и слабые места.

Коробка:
тип, число передач, обслуживание и известные проблемы.

Гибрид / электромобиль:
соответствующая информация о системе, батарее и зарядке.
Без бензиновых шаблонов там, где они неприменимы.

Не смешивай:
мощность ДВС, электромотора и суммарную мощность системы.
Не складывай их автоматически.

Сохраняй исходные единицы и смысл характеристик.
Не подменяй одно октановое обозначение другим без корректного основания.

«Отзывы владельцев» — именно отзывы, а не переименованная лента NHTSA complaints.

Показывай:
— повторяющиеся достоинства;
— повторяющиеся замечания;
— применимость;
— объём реально изученных материалов.

Жалобы официальной базы остаются отдельным типом сведений.

Количество уникальных материалов с темой не превышает размер выборки.
Повторы и перепечатки не увеличивают число независимых свидетельств.

Не возвращай «Какую версию брать» в отчёт об одном VIN.
Выбор между вариантами находится в сравнении.
Итог по одной машине — в её финальном выводе.


7. ЧЕЛОВЕЧЕСКИЙ ЯЗЫК И ПОЛЕЗНЫЙ ВЫВОД

Не повторяй возле каждого свойства:

«Расчёт / оценка».

«Сверьте таблички и документы».

Не называй отсутствие обнаруженных проблем доказательством исправности.

Ограничение дистанционного анализа кратко объясняй в финале.
Не превращай весь отчёт в отказ от мнения.

— стоит ли рассматривать автомобиль;
— для каких задач он хорош;

RU / AZ / EN:
одинаковый смысл и факты.

Аббревиатуры объяснять при первом использовании.

В основном интерфейсе не показывать:

8. ЧАТ, ФОТОГРАФИИ И PDF

Чат доступен в досье и сравнении.

Он знает:
— выбранную версию;
— данные объявления;
— историю при наличии;
— обсуждение пользователя.

«Спросить Auto Expert» не требует заново вводить автомобиль.

Примеры вопросов:

«Какой бензин нужен?»
«Что известно о проблемах этой коробки?»
«Почему этот вариант лучше второго?»
«Что меняется при моём пробеге?»

Используй существующий механизм ответов по источникам и доступного настроенного провайдера.

Не выдавай шаблонные ответы за полноценную свободную беседу.
Не представляй систему человеком или механиком, лично осмотревшим машину.

Фотографии разделяются на:

— фото объявления;
— архивные фото конкретного события;
— иллюстрации модели.

Подписывай происхождение.

Фото объявления не называй «до ремонта» без основания.
VIN для показа подтверждённых фотографий самого объявления не требуется.

PDF отражает тот же отчёт или сравнение:
источники, понятное оформление, финальный вывод в конце.

Фотографии включаются при наличии и допустимом использовании.

Не превращай PDF в печать экрана с кнопками и диагностикой.

Правила персонализации экспорта сохраняй.
Не создавай публичную ссылку на полный платный отчёт по умолчанию.

досье, сравнение, ссылки, галерея, PDF, чат.

Без оплаты и лимитов вопросов.

Полный доступ не означает разрешение автоматически покупать данные у внешнего поставщика.

Simulate User Paywall — отдельный режим, явно выключенный по умолчанию.
Он не включается при перезапуске самопроизвольно.

Не заставляй владельца смотреть техническую консоль ради полного доступа.

Основной интерфейс красивый и обычный.
Диагностика открывается отдельно.

Ограничения по владельцу данных, секретам и производственной среде сохраняются.

DEMO не смешивать с реальными результатами.
Синтетические аварии, фото, цены и отзывы не показывать как данные введённой машины.


12. ВИЗУАЛЬНЫЙ ДИЗАЙН

Сделай цельный профессиональный мобильный интерфейс.

Направление:

— светлая нейтральная основа;
— тёмный графитовый текст;
— один основной акцент: спокойный бирюзовый / синий;
— предупреждающие цвета только по смыслу;
— белые карточки;
— аккуратные границы;
— умеренные скругления и тени.

Чёткая иерархия:

автомобиль
→ основные характеристики
→ раскрываемые содержательные разделы
→ итог.

Никаких:
— огромных пустых баннеров;
— белого текста на пастельном фоне;
— россыпи emoji вместо иконок.

Основной текст удобен для чтения на телефоне.
Зоны нажатия не менее 48dp.

Проверь:
— увеличение системного шрифта;
— длинные названия комплектаций;
— азербайджанские символы;
— клавиатуру;
— системные панели Android;
— безопасные отступы.

Контент не должен заходить под системные панели.

Проверяй адаптивность в логических размерах экрана, а не только по физическому разрешению HONOR.

Прогресс показывает фактически выполняемую работу.
Завершение HTTP-запроса не означает автоматически «всё проверено».

Ошибки сети, недоступное объявление и недостаточное покрытие источников имеют разные понятные сообщения.

Сохраняй ввод, выбранные машины и контекст при возврате назад.
Не заставляй начинать сначала после открытия источника или PDF.


13. РАБОТА И ПРИЁМКА

Сначала коротко опиши план изменения текущих экранов и повторного использования кода, затем реализуй.

Не ограничивайся макетом, документацией или будущими интерфейсами.

Работай локально самостоятельно.

Не перекладывай на пользователя:
поиск файлов, PowerShell, запуск backend, установку APK и adb reverse.

Физическое подключение телефона, биометрия и разрешения Android могут требовать его участия.

Используй подключённый HONOR через имеющийся ADB.
Не запускай эмулятор и не скачивай system images.
Не отключай защиту других приложений.

Перед миграциями сохрани резервную копию пользовательских данных.
Не удаляй старые отчёты и не перезаписывай действующие снимки под видом обновления.

Подготовь устойчивый локальный запуск согласованной версии backend и клиента с нужным dev-origin.

Диагностика отличает:
— отсутствие backend;
— несовместимость API;
— ошибку загрузки данных.

Не требуй повторного ручного ввода переменных при каждом запуске.

Приёмка по пользовательским сценариям:

А. Разбор без VIN:
параметры → содержательный отчёт → чат → PDF.

Б. Объявление без VIN:
реальный импорт поддерживаемой страницы → контекст предложения → разбор без требования VIN.

В. VIN:
тот же разбор плюс действительно доступная история, без смешения экземпляров.

Г. Сравнение двух и трёх разных вариантов:
понятные различия → вывод → чат → PDF.

Д. Недоступный сайт или источник:
понятный запасной путь, сохранённый ввод, отсутствие выдуманных данных.

Проверяй разные бренды и типы силовых установок, не только один прежний автомобиль.

Новая машина не должна требовать добавления её фактов в production-код вручную.

Сохрани существующие проверки.

Добавь проверки:
— необязательности VIN;
— разделения данных продавца / версии / истории;
— изоляции сравниваемых автомобилей;
— DeveloperMode;
— языков;
— ошибок импорта;
— происхождения фото;
— совместимости APK/backend.

Успех — не только число зелёных тестов.
Нужны реальные понятные экраны и полезный результат для покупателя.
