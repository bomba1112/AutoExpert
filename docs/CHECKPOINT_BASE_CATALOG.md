## Разрешение конфликтов

- Elantra MY2020 EPA manual, ID 41436: исключён из импортируемого набора, поскольку заводской
  источник для 2.0 подтверждает IVT и отмену SE manual. Новая фиктивная запись не создавалась.
- Rio MY2019 EPA manual, ID 40695: существующая запись сохранена с новой ревизией
  `catalog_applicability=EXCLUDED`; фильтр и resolver её не предлагают. Причина — годовая
  заводская спецификация подтверждает только 6AT; окончательные выводы вне этого scope не делаются.
- BMW 330i MY2017/2018: ошибка Diesel в брошюре не перенесена; использованы заводские
  технические матрицы с бензиновыми двигателями.
- Passat MY2015: конфликтное значение колёсной базы в миллиметрах не опубликовано.
- Forte YD: EPA 2.0 automatic не позволяет надёжно разделить MPI и GDI. Созданы отдельные
  заводские варианты; расход EPA не перенесён на них произвольно.
- Sportage MY2022: отсутствующий блок двигателя на странице specifications дополнен годовым
  заводским overview, без догадки о внутреннем коде двигателя.

## Изменения pipeline

Активный режим — `BUILD_BASE_CATALOG`, manifest задан в
[`az-market-priority-policy.json`](../data/manifests/az-market-priority-policy.json).
Старые 51 исследованное семейство и результаты глубоких проверок сохранены как история,
но их старые ограничения не управляют текущим наполнением.

`scripts/run_base_catalog_batch.py` использует существующие import/review/publish стадии.
Он проверяет документальные ссылки, годовую применимость, хеш manifest и повторный запуск.
Данные добавляются manifest-ом. Для нового автомобиля не требуется отдельная ветка backend-кода.
Диапазон лет допускается только при доказательствах для каждого входящего года.

Готовность базового каталога выделена отдельно от `dossier_full`, цен, ownership-cost и изображений.
Добавлены совместимые необязательные параметры `catalog_ready_only` и фильтр поколения.
Resolver различает неподдерживаемый рынок и противоречащую комбинацию двигателя/коробки/поколения
в уже поддерживаемом рынке. При недостаточном различении нескольких вариантов сохраняется `MULTIPLE`.

## Локальное повторение и deployment package

Из корня существующего проекта с прежней локальной БД и кешем:

```powershell
.\.venv\Scripts\python.exe scripts/run_base_catalog_batch.py
.\.venv\Scripts\python.exe scripts/run_base_catalog_batch.py --publish-reviewed
.\.venv\Scripts\python.exe scripts/checkpoint_base_catalog.py
.\.venv\Scripts\ruff.exe check backend scripts
.\.venv\Scripts\python.exe -m pytest backend/tests -q
.\.venv\Scripts\python.exe scripts/package_verified_data.py
```

Checkpoint сохранности требует существующую резервную копию, указанную в скрипте; это аудит
именно данного локального пакета. Архивы source/deployment и QA обновлены, однако живая БД,
`.env`, credentials и частный кеш документов в них **не входят**. На новой БД необходимо
получить документы из разрешённых источников, заново сопоставить RawDocument IDs, подготовить
базовые ревизии и пройти review. Перенос готового локального состояния одной распаковкой архива
не заявляется. Старый portable fact bundle остаётся исследовательским baseline.
Развёртывание на Hetzner не выполнялось.
